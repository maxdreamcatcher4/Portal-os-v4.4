# MIGRATION_V2_TO_V3.md  
## Portal‑OS Unified Kernel OS → World OS

---

## 1. Overview

Portal‑OS v2 is the Unified Kernel OS: a graph‑driven, mesh‑based, constitutionally governed operating system where all v1 subsystems unify under a single kernel lattice.

Portal‑OS v3 is the World OS: a planetary‑scale operating system built on multi‑domain unification, global graph engines, world substrate, world identity, world governance, and multi‑domain cognition.

This document explains how each v2 subsystem evolves into its v3 counterpart and how the architecture transitions from unified → planetary.

---

## 2. Core Migration Principles

### A. Globalization of the kernel  
The Unified Kernel becomes the World Kernel, capable of multi‑domain unification and global lattice operations.

### B. Expansion of graph engines  
Runtime Graph becomes the World Runtime, operating across global graph nodes and world‑scale scheduling.

### C. Cognition becomes multi‑domain  
Cognitive Mesh becomes Multi‑Domain Cognition, with world agents, shared memory, and domain reasoning.

### D. TEC becomes world chains  
TEC Chains become World Chains, capable of cross‑domain execution and global chain scheduling.

### E. Substrate becomes planetary  
Substrate‑S becomes the World Substrate, with global consistency, resource pools, and world channels.

### F. Identity becomes federated  
Identity v2 becomes World Identity, with global auth, key federation, and world registry.

### G. Orchestration becomes global  
Orchestration Lattice becomes World Orchestration, with global consensus, world mesh, and global state sync.

### H. Governance becomes world constitutional  
Umbrella v2 becomes Umbrella v3, with world constitution, global chambers, and global voting graph.

### I. Security becomes multi‑domain isolation  
Security v2 becomes World Security, with global crypto, multi‑domain isolation, and global audit.

## 5. Migration Strategy

### Step 1 — Freeze v2  
No structural changes to portal-os-v2.

### Step 2 — Build v3 clean  
portal-os-v3 is a clean repo, importing v2 concepts but not v2 code.

### Step 3 — Map v2 subsystems to v3 equivalents  
Use the migration map above.

### Step 4 — Implement World Kernel first  
All other v3 systems depend on it.

### Step 5 — Integrate Umbrella v3  
Governance becomes world‑constitutional.

### Step 6 — Expand into global substrate and world simulation  
These complete the planetary OS.

```

    ↓
```

## 10. Compatibility & Versioning

### API Compatibility
V3 APIs are **not backward compatible** with V2.  
V2 systems remain frozen in portal-os-v2/.  
V3 is a clean evolution, not a patch.

### Cross-Domain Interop
V3 enables V2 domains to communicate via World Kernel.  
Intra-domain operations remain V2-native.  
Cross-domain operations route through World Orchestration.
